# CN selection and score contract

`cn-placement-relevance-v1` is owned by Corporate Network. Its six weighted components are hiring influence (30%), seniority (20%), company priority (20%), IIML relationship (15%), past responsiveness (10%), and warm-introduction potential (5%). The Directory UI calls the same pure component scorer used for profile assessment; the Directory SQL expression mirrors its option maps and is tested against the pure result. Provisional, unassessed profiles have `null` Placement Relevance. Data Confidence is a separate CN field and is not a component of this score.

`cn-selection-v1` is a named, saved criteria contract. CN D1 supplies current alumni fields and computes membership on preview and reconciliation. Dimensions are ANDed; selected programmes and seniorities are ORed within their dimensions. Manual exclusions win over criteria and inclusions. Membership is keyed by CN alumni ID, deduplicated, and separates selected records from those with a mapped Coresignal Employee ID. Missing provider mapping does not remove an alumnus from a cohort. Both the score version and selection version are required; unknown versions fail closed.

The standalone Intelligence repository stores the contract in its existing refresh-policy `filter_json` and holds only an inactive desired monitoring calendar. It must not use PostgreSQL `priority_score`, `priority_tier`, or mirrored profile facts as substitutes for CN Placement Relevance, CN Data Confidence, or authoritative D1 membership. There is no verified conversion between these metrics. A future activation milestone must authorize and implement fresh CN reconciliation before any provider run; present CN-owned policies cannot execute from stale PostgreSQL selection.

Calendar days are local to the configured IANA timezone. Weekly uses weekday 0–6 (Sunday–Saturday); monthly clamps day 29–31 to the month's last day; twice-monthly/custom days clamp independently and coalesced occurrences run once. DST gaps advance to the first valid local minute, and repeated local times choose the first instant. Desired cadence is distinct from event-driven provider webhooks. All new policies remain inactive; saving, previewing, and reconciling them performs no provider operation.
